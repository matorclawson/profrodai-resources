# Locked dependency review: 2026-10-27

sow: profrod-ops-SOW-01

This is the weekly maintainer review of the locked dependencies, due 2026-10-25. **One package changed: `qs` 6.16.0 to 6.16.1, in the npm lockfile only.** The Architect approved exactly that change in `ans_0e1e3fffeb2fe928`. No other bump is proposed, and `package.json` and `uv.lock` are unchanged.

## The one change

- **What:** `courses/agentic-coding-with-cursor/order-api/package-lock.json`, entry `node_modules/qs`: version 6.16.0 to 6.16.1, with the matching `resolved` URL and `integrity` value. No other line of the lockfile moved (`git diff` shows 3 lines removed and 3 added, all in that entry).
- **Why:** `npm audit` reported one moderate advisory on 6.16.0, GHSA-6pq8-jhm2-2vcw (CVSS 5.3), published 2026-10-27: `qs.stringify` with `arrayFormat: 'comma'` throws an uncaught TypeError when an array element has a non-callable own `toString`, a denial of service. Affected range 6.7.0 to 6.16.0; first patched version 6.16.1. The 2026-10-18 review found no advisory, so this one is new.
- **Inside the declared range:** `qs` is reached through `express` 4.22.3 and `body-parser` 1.20.9. Express declares `qs ~6.16.0`, which 6.16.1 satisfies, so no `package.json` change is needed. The bump was made with `npm update qs --package-lock-only`, which touches only the lock and does not add `qs` as a direct dependency.
- **Why not 6.17.0:** it is the latest release but lies outside Express's `~6.16.0` range. Taking it would need a range change or an override and would go beyond the patch. It is listed below as an observation, not a proposal.
